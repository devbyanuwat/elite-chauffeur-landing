# Hero ที่จับความสนใจได้ใน 3 วินาที

วันที่: 2026-07-28
ขอบเขต: `src/components/Hero.astro` · `src/components/sections/Booking.astro` (ใหม่) · `src/pages/index.astro`
ต่อยอดจาก: `docs/superpowers/specs/2026-07-27-landing-layered-parallax-design.md` (เอกสารนี้แก้ข้อ 1 ของฉบับนั้น ดูหัวข้อ 9)

## 1. ปัญหาที่วัดได้ ไม่ใช่ความรู้สึก

วัดในเบราว์เซอร์จริงด้วย CDP `Emulation.setDeviceMetricsOverride` (headless Chrome ธรรมดาปักความกว้างขั้นต่ำที่ 500px ถ้าไม่บังคับ emulation ตัวเลขที่ได้จะเป็นของปลอม)

| จอแรกปัจจุบัน | 1440×900 | 390×844 |
|---|---|---|
| บล็อกที่ตาต้องแยกแยะ | **19** | 9 |
| คำ | **52** | 24 |
| ตัวอักษรไทย | **364** | — |

คนอ่านไทยราว 200 คำ/นาที เท่ากับ 3 วินาทีได้ราว 10 คำ **ถ้าเริ่มอ่านทันที** ซึ่งไม่เกิดขึ้นจริง เพราะวินาทีแรกหมดไปกับการกวาดตาหาจุดโฟกัส งบจริงจึงอยู่ราว 6-8 คำบวกปุ่มเดียว ของปัจจุบันเกินงบราว 5 เท่า

**มือถือหนักกว่านั้น: ภาพมองไม่เห็นเลย** veil ไล่ 94%→99% ถูกทาบนกล่องสูง **2014px** ขณะที่จอสูง 844px ทุกพิกเซลที่มองเห็นจึงตกอยู่ในโซนทึบสุดของ gradient เห็นแค่เงาหมวกจาง ๆ ต้นเหตุคือ `.hero-bg` ใช้ `position: absolute; inset: 0` กินความสูงทั้ง section ทำให้องค์ประกอบแนวตั้งของ `object-position` ไม่มีผลทางคณิตศาสตร์

**ปัญหาที่ลึกกว่าจำนวนคำ**: ในภาพไม่มีรถ ไม่มีคนขับ มีผู้หญิงถือแผนที่ที่วัดไชยวัฒนาราม ส่วนข้อความพูดเรื่องคนขับ ใน 3 วินาทีสมองรับได้เรื่องเดียว ตอนนี้ภาพกับคำแย่งกัน — เอกสารนี้แก้ด้วยการ **ตัดของที่มาแย่งออก** ไม่ใช่แต่งคำใหม่ (ดูข้อ 6)

## 3. จอแรกที่ต้องการ

เหลือ **ไม่เกิน 5 ก้อน ไม่เกิน 14 คำ**

| ก้อน | ที่มา | หมายเหตุ |
|---|---|---|
| H1 | `hero.t1`-`hero.t4` เดิม ไม่แก้ข้อความ | ตัวใหญ่ขึ้น |
| ปุ่มหลัก | `hero.cta1` "ขอใบเสนอราคา" | ลิงก์ไป `#booking` |
| LINE | `hero.cta2` "ปรึกษาผ่าน LINE" | เปลี่ยนจากปุ่มใหญ่เป็นลิงก์ข้อความ ไม่แข่งกับปุ่มหลัก |
| `4.9★ จากลูกค้าจริง` | `hero.trust1` | บรรทัดเดียว |
| ตัวบอกว่ามีต่อข้างล่าง | ไอคอนล้วน `aria-hidden` | ไม่มีข้อความ |

ตัดออกจาก hero: badge `hero.badge` · ย่อหน้านำ `hero.lead` (25 คำ) · `500+` `hero.trust2` · `100%` `hero.trust3` · การ์ดฟอร์มทั้งใบ

`500+` กับ `100%` ไม่ได้หายจากเว็บ — แถบ Stats ใต้ hero ถืออยู่แล้ว การเก็บแค่ `4.9` ไว้ที่ hero ทำให้โค้ด**กลับมาตรงกับ spec ฉบับก่อนข้อ 7** ซึ่งเขียนไว้ว่า "hero ถือ 4.9 ตัวเดียว แถบ Stats ถือ 24/7 + 500+ + 100%" (final review จับได้ว่าโค้ดปัจจุบันถือครบสามตัว = ผิดข้อนี้อยู่)

## 4. เดสก์ท็อป (≥1024px)

ภาพเต็มจอ `min-height: 100svh` ภาพวิ่งใต้ nav ที่ `position: fixed` เธออยู่ซ้ายเหมือนเดิม ข้อความไปขวาตามทิศสายตาเธอ จัดกึ่งกลางแนวตั้ง

- คอลัมน์ข้อความ `width: min(100%, clamp(360px, 40vw, 520px))`
- `H1 { font-size: clamp(2.8rem, 5.2vw, 4.8rem) }` ไม่เกิน 2 บรรทัด
- **veil เปลี่ยนจากทาทั้งเฟรมเป็นบังเฉพาะหลังคอลัมน์ข้อความ** ค่าตั้งต้น `linear-gradient(102deg, transparent 0 42%, oklch(98% 0.008 75 / 0.55) 62%, oklch(98% 0.008 75 / 0.92) 100%)` ปรับได้ตามผลวัด contrast แต่ **ห้ามคืนไปเป็นการทาทั้งเฟรม** เพราะนั่นคือสาเหตุที่เจดีย์จางหายไป
- three.js depth field คงไว้ตามเดิม (gate 3 ชั้น: ≥1024px + motion allowed + WebGL2 · strength 0.03)

## 5. มือถือ (<1024px)

ส่วนที่เปลี่ยนมากที่สุด เพราะปัจจุบันมองไม่เห็นภาพเลย

- **`.hero-bg` ต้องมีความสูงของตัวเอง** เลิกใช้ `position: absolute; inset: 0` เปลี่ยนเป็นแถบเต็มความกว้าง `height: 52svh` ใต้ nav
- **ไม่มี veil เลยแม้แต่นิดเดียว** — ภาพโชว์เต็ม ไม่มีอะไรทับ
- `object-position` แนวตั้งกลับมามีผลเมื่อกล่องมีความสูงจริง ค่าตั้งต้น `32% 34%` ต้องยืนยันด้วยตาว่าหน้าเธออยู่ในเฟรมที่ 390px
- ข้อความและปุ่มอยู่ใต้แถบ บนพื้น `--bg-primary` — อ่านชัดเพราะไม่ต้องสู้กับภาพ
- `H1 { font-size: clamp(2.1rem, 8vw, 2.8rem) }`

## 6. กติกาเรื่องคำ

**ห้ามแต่งคำใหม่แม้คำเดียว** งานนี้ทำได้เฉพาะ *ลบ* ก้อนที่มาแย่งความสนใจ และ *ขยาย* ก้อนที่เหลือ ข้อความ H1 ใช้ของเดิมทั้ง 4 ท่อนไม่แตะ (`hero.t1`-`hero.t4` = "เดินทาง สบาย ๆ กับคนขับ มืออาชีพ" 6 คำ ซึ่งอยู่ในงบอยู่แล้ว)

ถ้าอยากได้พาดหัวที่ "ต่อประโยคที่ภาพเริ่มไว้" แนวไม่ต้องขับเอง/มีคนขับพาไป — เป็นการตัดสินใจเรื่องคำของคุณอนุวัชรกับหัวหน้าลูกค้า ไม่ใช่ของงานนี้ และต้องแก้ที่ dictionary `src/lib/i18n.ts` ทั้งไทยและอังกฤษพร้อมกัน

key ที่ถูกถอดออกจาก DOM (`hero.badge`, `hero.lead`, `hero.trust2`, `hero.trust3`) จะเหลือค้างใน dictionary โดยไม่มีใครใช้ — ปล่อยไว้ ไม่ต้องลบ เผื่อเอากลับ และการลบมีความเสี่ยงพังหน้าอื่นมากกว่าประโยชน์

## 7. ฟอร์มย้ายไปไหน

สร้าง `src/components/sections/Booking.astro` ย้ายการ์ด `.booking` ทั้งใบพร้อม `<BookingForm />` ออกจาก `Hero.astro` ไปไว้ที่นั่น **คง `id="booking"` ไว้เหมือนเดิม** แล้ววางใน `src/pages/index.astro` ต่อจาก `<Hero />` ทันที — scroll เดียวถึง

id และ selector ที่ห้ามเปลี่ยน เพราะมีคนอื่นเรียกอยู่:

| ตัว | ใครเรียก |
|---|---|
| `#booking` | ปุ่ม `hero.cta1`, ปุ่ม "จองรถ" บน nav, สคริปต์ใน `Fleet.astro` |
| `#b_pickup` | `Fleet.astro` สั่ง focus หลัง scroll |
| `.vtype-chip` / `#vehicleType` | `Fleet.astro` ตั้งค่าประเภทรถก่อน scroll |

## 8. Motion

- **ถอดคลาส `reveal` ออกจาก `.hero-copy`** — `motion.css` ตั้ง `.js-motion .reveal { opacity: 0 }` แปลว่า H1 ซึ่งเป็น LCP ถูกซ่อนจนกว่า JavaScript จะรัน ผิดกติกาข้อ 1 ของ spec ฉบับก่อนที่เขียนว่า "LCP element ห้ามอยู่ในชั้นที่ JS ขยับ" หลังแก้ H1 ต้องเห็นทันทีที่ HTML มาถึง
- ไม่เพิ่ม entrance animation ให้ H1 ความเคลื่อนไหวใน hero มาจาก depth field อย่างเดียว ซึ่งทำงานทันทีที่โหลดเสร็จโดยไม่ต้องรอให้คนเลื่อน
- ไม่แตะ `pin.ts`, `legacy-reveal.ts`, `contract.ts`, `tiers.ts`

## 9. สิ่งที่เอกสารนี้ทับของเดิม

1. **spec 2026-07-27 ข้อ 1** เขียนว่า "การจัดวางใหม่ต้องไม่ทำให้ฟอร์มขอราคาหายไปจากสายตา" — คุณอนุวัชรตัดสินเมื่อ 2026-07-28 ให้ย้ายฟอร์มลงล่างทั้งหมด ผมแจ้งความขัดแย้งนี้ก่อนถามและได้คำตอบเดิม จึงถือว่าเอกสารนี้ทับข้อนั้น **ความเสี่ยงที่ยอมรับ**: จำนวนคนเริ่มกรอกฟอร์มอาจลดลง เพราะไม่เห็นฟอร์มบนจอแรก ตัวชดเชยคือปุ่มหลักพาไปถึงใน scroll เดียว ฟอร์มเป็นสิ่งถัดไปทันที และปุ่ม LINE ลอยยังอยู่
2. **`.impeccable.md` และ `CLAUDE.md`** หัวข้อ palette ที่เขียนว่า off-white/charcoal muted — ต้องแก้ให้ตรงกับของจริงว่า UI รอบนอกเป็นสีนิ่งตามเดิม ส่วน hero เป็นภาพท่องเที่ยวสีสดหนึ่งภาพที่ถูกกรอบด้วยสีนิ่งนั้น ถ้าไม่แก้ session ถัดไปจะย้อนงานทิ้งด้วยเหตุผลว่า "ผิด brief"

## 10. วัดยังไงว่าสำเร็จ

ทุกข้อวัดในเบราว์เซอร์จริงด้วย CDP + `Emulation.setDeviceMetricsOverride` ที่ **1440×900** และ **390×844** ห้ามใช้ headless ธรรมดาเพราะมันปักความกว้างขั้นต่ำ 500px

| เกณฑ์ | ค่าที่ต้องได้ |
|---|---|
| ก้อนบนจอแรก | ≤ 5 |
| คำบนจอแรก | ≤ 14 |
| ความสูง `.hero-bg` บนมือถือ | ≤ 60% ของความสูง section |
| ค่า alpha ของ veil บนมือถือ | 0 (ไม่มี veil) |
| contrast ของ H1 กับพื้นหลังใต้มัน | ≥ 4.5:1 ทั้งสองขนาดจอ |
| หน้าของเธอบนมือถือ | อยู่ในเฟรม ไม่โดนอะไรทับ (ยืนยันด้วยภาพหน้าจอ) |
| `opacity` ของ H1 เมื่อปิด JavaScript | 1 |
| `#booking` | กดถึงจาก 3 ทาง (ปุ่ม hero, ปุ่ม nav, ปุ่มในการ์ดรถ) และ `#b_pickup` ยัง focus ได้ |
| เทสต์ | ≥ 72 ผ่าน |
| build | 0 error ไม่มี warning ใหม่ |
| คำที่เปลี่ยน | 0 (นอกจากก้อนที่ระบุให้ลบในข้อ 3) |

ถ้าข้อไหนไม่ผ่าน ให้บันทึกค่าจริงแล้วรายงาน **ห้ามขยับเกณฑ์ให้ผ่าน**
